# からくりポケット（AI指示書ループ自律開発システム）

ガスマネージャーを自律的に高速改修・保守するための「モデル間リレー協調開発」の型です。

設計役（大型推論モデル：Claude 3.7 Sonnet / Opus / GPT-4o 等）と作業役（超高速・高スループットモデル：Gemini 2.0 Flash 等）を指示書と関所テストで繋ぎ、トークン使用量を節約しながら 100% 確実にゴールまで完走させます。

---

## 仕組み（からくりポケットの型）

```
[設計役（番頭）]
   │
   ▼ 課題・合格条件を明確にした指示書を作成
[queue/XXX_指示書.md]
   │
   ▼ 作業役（フラッシュ君）が番号順に検知して自律実行
[ローカル実装・テスト・デプロイ]
   │
   ├─ 全関所PASS ──► [queue/reports/XXX_report.md] を書き、待機シグナル (_idle.txt)
   └─ 不合格    ──► [queue/reports/_stopped.txt] を書き、作業停止して設計役へ通知
```

---

## フォルダ構成

```
queue/
├── README.md                     # 本ドキュメント（ループの決まり）
├── 001_sample_テンプレート指示書.md # 指示書の書き方サンプル
└── reports/                      # 完了報告書の格納フォルダ
    ├── .gitkeep
    └── XXX_report.md             # 指示書ごとの完了報告書
```

---

## ループの決まり（作業AIの行動規範）

1. **未着手指示書の特定**:
   `queue/` フォルダ内の指示書（`001_*.md`, `002_*.md`...）を番号の小さい順に走査し、`reports/<同じ番号>_report.md` が**まだ存在しない**最初の指示書を特定して着手する。
2. **ピンポイント修正**:
   指示書に書かれたファイル・関数のみを修正し、指示されていない周辺コードのリファクタリングや改変を一切行わない。
3. **関所（合格条件）の全件物証確認**:
   指示書に記載された「合格の条件」をすべて実機コマンド（`py gas.py diagnose`, `py gas.py verify-ui`, `pytest` 等）で実行する。
   - 1つでも外れた場合は作業を中断し、`reports/_stopped.txt` に理由を記録して停止する。
   - ツール出力の末尾（PASS）だけでなく、ログの途中経過（警告・件数・変更差分）を指差し確認する。
4. **報告書の作成**:
   すべての関所をクリアしたら `reports/<番号>_report.md` を作成する。
   - 先頭に「指示にない足し」「消した行」を自己申告する。
   - 実機のコマンド出力結果を省略せずに貼る。
5. **完了待機シグナル**:
   作業完了後、`reports/_idle.txt` に現在時刻を書き込み、チャットには「書きました（からくりポケットは空）」とだけ返して自律停止する。

---

## 指示書の書き方（設計役のルール）

指示書は作業AIが推論で迷わないよう、以下の4項目を必ず含めて記述します。

1. **背景と目的**: 何が問題で、どう直す必要があるのか
2. **直す所**: 対象ファイル、行番号の目安、修正方針
3. **合格の条件（関所）**: これが通らなければ合格と認めない具体的コマンドと期待値
4. **報告形式**: 報告書に貼るべきログや確認項目
